Introduction to Key Terms

The Arm architecture uses a set of terms that are crucial for programmers to understand, often written in small capital letters and having specific meanings. In this section, we will explore the most common terms and their implications, including Processing Element (PE), which is a generic term for an implementation of the Arm architecture.

Key Architecture Terms

  • A Processing Element (PE) refers to any component that has its own program counter and can execute a program, such as a core in the Arm Cortex-A processors.
  • Key insight: Implementation Defined (IMP DEF) features are defined by the specific micro-architecture and must present a consistent behavior or value.
  • In practice, the size of the caches is IMP DEF, meaning that the architecture provides a defined mechanism for software to query the cache sizes, but the actual size of the cache is determined by the processor designer.
  • Unpredictable and Constrained Unpredictable behaviors are terms used to describe behaviors that software should not rely on, such as providing a misaligned translation table, which is advanced and represents bad software that violates the architectural rule.
  • Deprecated features are being removed from the architecture, such as the uses of the IT instruction and certain barrier instructions, which are deprecated for performance reasons.

Understanding the Implications

Understanding these terms is crucial for programmers to write efficient and reliable code. By knowing what each term means, developers can make informed decisions about how to use the Arm architecture and avoid potential pitfalls, such as assuming that features are always available or behave in a certain way, which is not always the case. By being aware of the Unpredictable and Constrained Unpredictable behaviors, developers can write more robust code.
